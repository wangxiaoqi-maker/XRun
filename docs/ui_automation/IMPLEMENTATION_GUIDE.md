## 二、核心功能模块

### 模块1：设备投屏 🖥️

**目标**：将手机屏幕实时显示在网页上，支持在网页上操作手机

#### 技术方案对比

| 方案 | 帧率 | 延迟 | 实现难度 | 推荐指数 |
|------|------|------|----------|----------|
| **ADB截图轮询** | 5-15 FPS | 100-300ms | ⭐ 简单 | ⭐⭐ |
| **scrcpy + FFmpeg** | 30-60 FPS | 35-70ms | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐⭐ |
| **ws-scrcpy** | 60 FPS | 35ms | ⭐⭐ 简单 | ⭐⭐⭐⭐ |
| **minicap** | 60 FPS | 20-50ms | ⭐⭐⭐⭐ 复杂 | ⭐⭐⭐ |

#### 推荐实现路径

**方案A：ADB 截图轮询（MVP 阶段）**
```
实现思路：
1. 后端定时执行：adb exec-out screencap -p
2. 将 PNG 转 base64，通过 WebSocket 推送给前端
3. 前端用 Canvas 或 <img> 渲染
4. 用户点击 Canvas，计算坐标比例，发送给后端
5. 后端执行：adb shell input tap x y

优点：实现简单，2-3天可完成
缺点：帧率低，体验一般
适合：MVP 验证阶段
```

**方案B：集成 ws-scrcpy（推荐生产环境）**
```
实现思路：
1. 部署 ws-scrcpy 服务（Node.js）
2. 前端直接连接 ws-scrcpy 的 WebSocket
3. 或者 iframe 嵌入 ws-scrcpy 页面
4. 通过其 API 获取控制能力

优点：开箱即用，体验好
缺点：需要额外部署服务
```

**方案C：自建 scrcpy 管道（高级）**
```
实现思路：
1. Python 启动 scrcpy 进程，捕获视频流
2. FFmpeg 转码为 MJPEG
3. 通过 WebSocket 或 HTTP 流推送
4. 前端解码渲染

优点：可控性强
缺点：实现复杂
```

### 模块2：操作录制 🎬

**目标**：记录用户操作，生成可回放的测试用例

#### 技术方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **Web端录制** | 捕获投屏页面的点击事件 | 简单直接 | 依赖投屏准确性 |
| **getevent监听** | 监听 Linux 内核触摸事件 | 精确、原生 | 事件解析复杂 |
| **Accessibility** | 监听 UI 事件 | 有语义信息 | 需要开启权限 |

#### 推荐实现路径

**方案A：Web 端录制（推荐起步）**
```
实现思路：
1. 用户在投屏页面上操作
2. 前端监听 Canvas 的 mousedown/mouseup/mousemove
3. 计算操作类型：
   - 点击：按下-抬起，移动距离 < 10px
   - 滑动：按下-移动-抬起，移动距离 > 50px
   - 长按：按下时间 > 500ms
4. 坐标转换：Canvas坐标 → 设备坐标
5. 操作执行：通过 ADB 执行对应操作
6. 截图保存：每次操作前后各截图一张
7. 生成用例 JSON

优点：
- 所见即所录，用户体验好
- 不依赖设备端能力
- 可以边录边执行

注意事项：
- 坐标转换要考虑缩放比例
- 需要处理投屏延迟带来的误差
```

**方案B：getevent 录制（精确场景）**
```
实现思路：
1. 启动监听：adb shell getevent -lt
2. 解析事件流：
   - ABS_MT_TRACKING_ID：触摸开始/结束
   - ABS_MT_POSITION_X/Y：坐标
   - SYN_REPORT：事件边界
3. 识别手势类型
4. 记录时间戳

难点：
- 多点触控处理
- 不同设备事件格式可能不同
- 需要较多调试
```

### 模块3：用例编辑 ✏️

**目标**：支持创建、编辑、增强测试用例

#### 功能设计

```
1. 基础编辑
   - 步骤列表展示（可拖拽排序）
   - 添加/删除/修改步骤
   - 步骤截图预览

2. AI 增强
   - 根据截图自动生成元素描述
   - 将坐标操作转换为语义操作
   - 例：{"tap": [540,1200]} → {"ai_tap": "点击登录按钮"}

3. 两种操作模式
   - 坐标模式：精确但脆弱
   - AI模式：智能但稍慢
   
4. 参数化支持
   - 变量定义：${username}
   - 数据驱动测试
```

#### 步骤类型设计

| 类型 | 用途 | 参数 |
|------|------|------|
| `tap` | 坐标点击 | x, y |
| `ai_tap` | AI智能点击 | ai_prompt |
| `swipe` | 滑动 | start_x/y, end_x/y, duration |
| `input` | 输入文本 | text, (ai_prompt) |
| `assert` | 断言验证 | ai_prompt |
| `wait` | 等待元素出现 | ai_prompt, timeout |
| `sleep` | 固定等待 | duration_ms |
| `back` | 返回键 | - |
| `launch` | 启动应用 | package_name |

### 模块4：用例执行 ▶️

**目标**：使用 Midscene AI 执行测试用例

#### 执行引擎架构

```
┌─────────────────────────────────────────────────────────┐
│                    FastAPI 后端                          │
│  ┌──────────────┐      ┌──────────────────────────────┐ │
│  │ 执行任务队列  │      │ WebSocket 日志推送           │ │
│  └───────┬──────┘      └──────────────────────────────┘ │
│          │                                               │
│          ▼                                               │
│  ┌──────────────────────────────────────────────────┐   │
│  │              子进程调用 Node.js                    │   │
│  │  node executor.js case.json 83d2c1ef             │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                 Midscene 执行器 (Node.js)                │
│  ┌────────────────┐  ┌─────────────────────────────┐   │
│  │ AndroidInterface│  │ createAgent()              │   │
│  │ - screenshotBase64                              │   │
│  │ - tap(x, y)     │  │ - aiTap("...")             │   │
│  │ - swipe(...)    │  │ - aiAssert("...")          │   │
│  │ - input(text)   │  │ - aiWaitFor("...")         │   │
│  └────────────────┘  └─────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    AI 模型服务                           │
│  豆包 UI-TARS / 智谱 GLM-4V / OpenAI GPT-4V             │
└─────────────────────────────────────────────────────────┘
```

#### 执行流程

```
1. 接收执行请求（case_id, device_id）
2. 从数据库获取用例 JSON
3. 启动 Node.js 子进程执行
4. 实时捕获 stdout，推送日志
5. 执行完成，收集报告
6. 更新执行结果到数据库
```

#### 两种执行策略

```
策略A：纯坐标回放
  - 直接用 adb 执行坐标操作
  - 快速但不稳定（UI变化会失败）

策略B：AI 智能执行（推荐）
  - 使用 Midscene 的 aiTap/aiAssert 等
  - AI 分析截图，智能定位元素
  - 容错性强，但需要 AI API

策略C：混合模式（最佳实践）
  - 优先使用 AI 定位
  - AI 失败时降级到坐标
  - 记录降级情况，用于优化
```

### 模块5：报告生成 📊

**目标**：生成可视化测试报告

#### 报告内容

```
1. 基本信息
   - 用例名称、执行时间
   - 设备信息
   - 执行结果（成功/失败）

2. 步骤详情
   - 每步操作截图
   - AI 分析过程（如有）
   - 耗时统计
   - 失败原因（如有）

3. 统计信息
   - 成功率
   - 平均执行时间
   - AI 调用次数和耗时
```

#### 实现思路

```
方案1：利用 Midscene 内置报告
  - Midscene 执行后自动生成 HTML 报告
  - 直接收集展示即可

方案2：自定义报告
  - 执行过程中收集数据
  - 用模板引擎生成 HTML
  - 支持导出 PDF
```

## 三、技术选型总结

| 层级 | 技术 | 说明 |
|------|------|------|
| **后端框架** | FastAPI | 异步、高性能、自动文档 |
| **数据库** | SQLite / PostgreSQL | SQLite 够用，PostgreSQL 更强 |
| **前端框架** | Vue 3 / React | 看团队熟悉程度 |
| **UI 组件** | Element Plus / Ant Design | 开箱即用 |
| **投屏** | scrcpy / ws-scrcpy | 推荐 ws-scrcpy |
| **AI 执行** | Midscene.js | 已验证可行 |
| **AI 模型** | 豆包 UI-TARS | 国内可用，效果好 |

## 六、难点与解决方案

| 难点 | 解决思路 |
|------|----------|
| 投屏延迟高 | 先用截图轮询跑通，后期集成 scrcpy |
| 事件录制复杂 | 用 Web 端录制代替设备端录制 |
| AI 定位不准 | 混合模式 + 手动调整 + 优化 prompt |
| 多设备并发 | 任务队列 + 进程池 |
| 不同分辨率适配 | 使用比例坐标或 AI 定位 |

## 七、MVP 验收标准

```
✅ 能看到手机屏幕（5-10 FPS 即可）
✅ 能在网页上点击操作手机
✅ 能录制操作生成用例
✅ 能编辑用例步骤
✅ 能用 Midscene 执行用例
✅ 能看到执行结果

❌ 不需要：高帧率投屏
❌ 不需要：复杂手势支持
❌ 不需要：完美的 UI
```
